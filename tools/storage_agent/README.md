# وكيل التخزين المحلي (noona-agent)

برنامج صغير يثبت على جهاز أو خادم **داخل الشركة** ويحفظ ملفات أرشيفها على أقراصها، بينما يعمل النظام على السحابة أو في مركز بيانات.
الوكيل هو من يتصل بالنظام (HTTPS صادر فقط)، فلا يلزم فتح أي منفذ في شبكة الشركة. ملف واحد بلا متطلبات إضافية.

| الملف | النظام |
|---|---|
| `dist/noona-agent-windows-amd64.exe` | Windows 10/11 وWindows Server (64-bit) |
| `dist/noona-agent-linux-amd64` | Linux x86-64 |
| `dist/noona-agent-linux-arm64` | Linux ARM64 (مثل أجهزة NAS الحديثة) |

## التثبيت

1. في النظام: **المستندات ← مكان حفظ الملفات ← وكلاء التخزين المحلي**: اكتب اسماً للوكيل ← «إضافة وكيل وإصدار مفتاحه».
   يظهر **عنوان النظام** و**المفتاح** مرة واحدة فقط؛ انسخهما.
2. على جهاز الشركة: انسخ البرنامج إلى مجلد (مثل `C:\NoonaAgent`) وأنشئ بجانبه `noona-agent.json`:

   ```json
   {
     "server": "https://<server>/ords/noona/agent/v1/",
     "key": "nsa_...",
     "path": "D:\\NoonaArchive"
   }
   ```

   `path` مجلد الحفظ (يفضل قرصاً له نسخ احتياطي). `poll` اختياري: ثواني بين طلبات المهام (الافتراضي 2).
3. اختبر: `noona-agent.exe test` ← يجب أن يظهر `OK`.
4. ثبّت كخدمة تعمل مع بدء الجهاز (موجه أوامر **كمسؤول**): `noona-agent.exe install`
   - Windows: مهمة مجدولة `NoonaStorageAgent` بحساب SYSTEM. Linux: `sudo ./noona-agent install` (خدمة systemd `noona-agent`).
5. في النظام تظهر حالة الوكيل «متصل» خلال دقيقة. اختر **«وكيل تخزين محلي»** والوكيل ← «حفظ» ← «اختبار الاتصال».
   لنقل الملفات القديمة: «نقل ملفات قاعدة البيانات إلى مكان الحفظ الحالي».

## كيف يعمل

- **الحفظ**: الملف الجديد يبقى في النظام حتى يحمله الوكيل ويحفظه ويعيد بصمته SHA-256؛ لا يحذف من النظام إلا عند تطابق البصمة.
  الملفات تحفظ في `path/السنة/الشهر/` بأسماء داخلية لا تكشف محتواها.
- **العرض**: النظام يطلب الملف من الوكيل فيرسله خلال ثوانٍ (يتحقق النظام من بصمته)، وتبقى نسخة مؤقتة ساعة ثم تحذف.
- **انقطاع الوكيل**: الرفع مستمر (الملفات تبقى في النظام وتنقل عند عودته)، وعرض الملفات المحفوظة عنده يظهر رسالة واضحة حتى يعود.
- **المهام**: مهمة لم تنجز خلال 5 دقائق تعاد، وبعد 5 محاولات فاشلة تسجل فاشلة مع سببها في شاشة الوكلاء.
- **الأمان**: المفتاح لا يحفظ في النظام (بصمته فقط)؛ «مفتاح جديد للوكيل» يوقف القديم فوراً، و«إيقاف الوكيل» يمنعه من الاتصال.
  الوكيل لا يصل إلا لملفات شركته، ولا يقبل مسارات خارج مجلد الحفظ.

## التوقف عن استخدام الوكيل

اختر «داخل قاعدة البيانات» ← «حفظ» ← «نقل ملفات قاعدة البيانات إلى مكان الحفظ الحالي»: يطلب النظام كل الملفات من الوكيل ويحفظها
نهائياً بعد مطابقة بصمتها. بعد اكتمال النقل (عمود «عند وكيل الشركة» يختفي) أوقف الوكيل، ثم `noona-agent.exe uninstall`.
نسخة الملفات على جهاز الوكيل لا تحذف تلقائياً.

## السجل والبناء

السجل في `noona-agent.log` بجانب البرنامج. البناء من المصدر (Go 1.22+):

```bash
cd tools/storage_agent
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o dist/noona-agent-windows-amd64.exe .
CGO_ENABLED=0 GOOS=linux   GOARCH=amd64 go build -trimpath -ldflags "-s -w" -o dist/noona-agent-linux-amd64 .
CGO_ENABLED=0 GOOS=linux   GOARCH=arm64 go build -trimpath -ldflags "-s -w" -o dist/noona-agent-linux-arm64 .
```

واجهة النظام للوكيل (ORDS): `db/ords/agent_v1.sql`، والمنطق: `db/plsql/132_noona_dms_agent_pkg.sql`، والاختبار: `db/tests/test_storage_agent.sql`.
